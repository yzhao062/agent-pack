# Polish

The style rules live where every agent already reads them: `AGENTS.md` (Writing Defaults, Formatting Defaults, and the composed `agent-style` pack with its House Style), the `author-voice` skill, and the `/vet` review lenses in `implement-review/references/review-lenses.md`. Resolve `implement-review` and `author-voice` through the skill lookup order in `AGENTS.md`. A path that begins with `scripts/` is in this skill's directory.

## Scope

- **Target.** The files the user names, and a section or one round's edits when named. Edits go in place, so the git diff is the review surface. Run `git status` first and tell the user when the target already has uncommitted edits, since the diff will mix them with this pass. Every intermediate file (a baseline, a section copy, a build, a probe script) goes in the session scratchpad, never in the repository.
- **One round's edits.** Stage the round, then run the style audit without file arguments or `--all-lines`: it audits the staged copy, keeps line findings on changed lines, and keeps a document-level finding for each changed file. Leave the pass unstaged so `git diff` shows it alone. In a scratch copy outside git, audit each changed file whole and keep the document-level findings and the findings on changed lines. Never paste lines from several places into one file, since the detectors read it as one paragraph.
- **Kind.** A paper or proposal gets every step. Other technical writing (README, docs, report, email draft) gets the steps not marked *paper or proposal*.
- **Mode.** `review` (or "just review") stops after step 2. Otherwise run all steps, also when `/polish` is one step of a larger task: a nested pass runs every step, and its report comes before the task goes on.
- **Writer.** The agent that runs this skill as the coordinator makes the edits, whether Claude Code or Codex. A `/polish` request is the user's choice of writer for that draft, so it overrides the profile pack's default that Claude drafts prose a person will read. The content rules below bind every writer. A worker dispatched by `prun` or `/vet` does not run this skill.
- **Lead author.** `author-voice` reproduces the user's own voice. When a paper's lead author appears to be someone else, ask before applying it.
- **Local rules.** Read the repository's `AGENTS.local.md` and any style source it names. Where they set a genre's conventions (a federal proposal's opening, a peer review's register, an email template's punctuation), they govern that draft: report a departure from the shared defaults, and do not edit toward the default.

## Content and Expression

A polish makes the draft read well without changing its scientific content. Content belongs to the document: any sentence may be rewritten around it, and a summary section selects from it under the rules below.

- **Content stays.** Every fact, number, citation, link, definition, and result the document states stays in it, at its strength and scope. Each qualifier that limits what the evidence supports also stays, including a guarantee or hedge on stated behavior ("never", "may", "once") and the reason a contrast or gap is unresolved. A tie, a loss, and a marker of exploratory, post-hoc, or review status stay as well. A stated relation keeps its kind: a cause stays a cause, and parallel claims stay parallel. Never add a fact, number, citation, link, definition, result, or relation the document does not state, including a relation asserted only by a connective. List a change to content or a move to another section for the author, and do not apply it. Narrowing or reframing a headline claim is a change to content.
- **Expression is open:** word choice, sentence structure and length, the subject, voice, and person, splitting and joining sentences, the order of sentences and ideas within a section, and a relation word that names a relation the text states. An interval may leave the prose when a table in the same section reports it for the same estimate. Cut repetition the document still states. A general limitation repeated outside Limitations (Risks and Alternatives in a proposal) may go only when Limitations states it. A defense against an objection nobody raised, or a caveat tail attached by habit, may go only when it adds no fact, qualifier, or reason.
- **A summary section selects.** An abstract, introduction, or conclusion restates the body within the figure budget of the House Style and the `author-voice` template. It keeps its answer to the paper's main question, with the population, the comparison, and every exception, tie, loss, or uncertainty that bounds that answer. Each result it keeps stays at its strength, with its qualifier beside it. A detail is secondary when leaving it out gives the reader the same answer at the same strength and scope. Such a section may leave out a secondary detail, or round a figure, when the body or a table states that result at its original precision. When a result's role is unclear, keep it.
- **Rewrite by default.** Rewrite a passage that reads badly around every protected piece above. If a wording might change a protected piece, try another; if none keeps it and reads well, keep that claim as written, edit around it, and list the proposed change for the author. If only the phrasing is in doubt, rewrite. A rule departure that reads well may stay.

## Steps

1. **Baseline.** Record each target's word count, and for a revision the count in the last commit (`git show HEAD:<file>`).
2. **Review, read-only.** Collect findings, each with its location, in three groups: *must fix* (a banned word, a claim the evidence does not support in either direction, a fact to verify), *should fix* (a passage that reads badly), and *consider* (a rule departure that may read well). At the end of step 2 and before any edit, show the list to the user in a message, with "none" for an empty group, and in a full pass go on without waiting. The reading pass below adds an entry naming the lens items applied and the passages read, even when it finds nothing.
   - Run `<python> <implement-review>/scripts/style-audit.py --repo <repo> --all-lines <file>`, or the round form above. It always exits 0; read `Style status:` and the rules it reports as partly or not covered, and audit those by reading the rule pack. Judge each finding; one you dismiss goes in the list with the reason.
   - *Paper or proposal:* run author-voice step 4's `voice_check.py` on each section with its `--section` value, and put each `CHECK` in the list with its section. A section that shares a file with other text is copied alone into the session scratchpad first.
   - Read each paragraph whole, as its intended reader would. Judge it against the rules, the House Style, and the Writing Defaults on figures and intervals, and list every paragraph that reads badly with the reason. Then read for what no script sees, using the review lenses: for any prose, General items 7 and 8; for a paper, the Paper preamble (undersell and overclaim, accretion) and items 1, 4, 7, and 8; for a proposal, the common proposal dimensions. Compare growth against the baseline.
   - *Paper or proposal:* for each section checked with `--section` `abstract`, `introduction`, or `conclusion`, read the body it summarizes and the `author-voice` template and exemplars for that section here, before any edit, then compare the section with them. A gap that the document's content can fill is a *should fix*, applied when cuts pay for its words and otherwise listed for the author. Within the requested scope, give the section a verdict in the list, with the reason: *redraft* when it carries more figures than the House Style and the template allow, more labels or terms than a first read can hold, or moves in an order that loses the thread, otherwise *edit in place*. When the problem reaches past the requested scope, describe the larger rewrite for the author.
3. **Polish in place.** First save the targets with `<python> scripts/content_check.py snapshot --repo <repo> --out <scratchpad>/<fresh-dir> <file>...`. Then rewrite each passage step 2 flagged until it reads well, in the author's voice for a paper or proposal, keeping its content. Edit a whole paragraph when the problem is the paragraph:
   - Of the *must fix* items, replace each banned word. A claim the evidence does not support and a fact to verify go to the author unchanged.
   - Redraft a section marked *redraft* along the template and exemplars read in step 2, with the document as the source of its facts and under author-voice step 3's firm rules, and keep its answer with every bound on it. For a section marked *edit in place*, let its template guide the edits.
   - Reread the passage behind each `voice_check` `CHECK` or audit count, and never edit only to move the number.
   - Keep the format (LaTeX macros, labels, citations, comments, Markdown structure) and any page or word limit. A file's word count stays or falls; a sentence may gain the words clarity needs when cuts elsewhere pay for them.
4. **Recheck.**
   - Rerun the style audit and, for a paper or proposal, `voice_check.py`. For one round's edits, name the changed files, since the no-argument form reads the staged copy, which does not hold the pass. A named file is audited whole, so keep only the document-level findings and those on lines that `git diff HEAD -U0` marks as changed. Treat a remaining finding by step 3's rules: fix it, keep it with a specific reason, or, for a claim or a fact, leave it unchanged and report it to the author.
   - After the last edit, run `<python> scripts/content_check.py compare --repo <repo> --baseline <that dir> <file>...`. It lists each number, citation, link, label, cross-reference, and math expression it recognizes whose count changed in a target, with nearby files that hold the same token as leads. It exits 0 after the report even when counts changed, and stops with an error when the baseline is missing. Match each change that rests on backing to that backing: a detail left out or a figure rounded in a summary section to the body passage or table cell that states the same result at its original precision, a detail a summary takes from the body to the passage it restates, an interval cut from the prose to the same estimate and interval in the section's table, and a cut of repetition to the passage that still states it. Look in the target and in each file named as a lead. A lead shows only that the same token appears elsewhere, and the target may hold backing that no lead names. Keep a backed change when its backing exists and the reader still gets the same answer at the same strength and scope; otherwise undo that change.
   - A count cannot tell which claim a number belongs to, and it sees no swapped value, qualifier, strength, or relation. Compare both sides of every changed passage with the baseline, deleted passages and edits with equal counts included. Keep what Content and Expression permits, restore any lost protected piece, and correct any new assertion or changed attachment. If an edit follows a check, run that check again on the final text. After any correction, run the comparison and this reading again.
   - Run `git status`: only the target files may show changes from this pass, and anything else the pass created moves to the session scratchpad.
5. **Report in the reply, never in the file,** when the pass ends.
   - Files and sections changed, and word count before and after, with the change against the baseline.
   - The outcome of every step 2 finding, each `CHECK` included, by location: fixed, with the wording before and after, or for a rewritten paragraph what changed and why; kept, with the reason; or left for the author (a proposed content change with its doubt, a fact to verify, a move to another section). An edit that answers no finding is listed as "taste" with its wording.
   - The `content_check` summary line; each cut with its reason; each detail left out, figure rounded, or interval taken from the prose, with the passage or table cell that backs it; style-audit findings before and after; and the last `voice_check` summary line with any `CHECK` kept and why.
   - Next steps: `git diff` to accept or discard hunks, and `/vet` for an independent read before a submission.

Keep the run to one agent. An independent second read is `/vet`'s job, and this skill never dispatches it.
